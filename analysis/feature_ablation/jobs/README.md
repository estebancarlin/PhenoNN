# Feature-ablation jobs

The `run_*.sh` files are generated by `analysis.feature_ablation.gen_jobs` into
`runs/feature_ablation/jobs/`. They are gitignored. Do not edit them by hand.

The two committed wrappers are the stable entry points. Both generate job
scripts, add the cluster options, and submit them. On HAL the paper profile
defaults to `SUBSET=0.25` and `PHENONN_MEM=120G`; use `SUBSET=0.5` on
larger-memory systems.

Run these examples from the repository root with the analysis environment
loaded:

```bash
export RUNS="$PWD/runs"
export FA_ROOT="$RUNS/feature_ablation"
```

## `submit_ablate.sh`

Generates the per-feature study and submits it. With `STUDY=groups` it runs the
grouped leave-one-group-out sweep instead.

```bash
OUTPUT_DIR="$FA_ROOT" PHENONN_SITE=hal \
    bash analysis/feature_ablation/jobs/submit_ablate.sh --study features
```

```bash
OUTPUT_DIR="$FA_ROOT" PHENONN_SITE=hal \
    bash analysis/feature_ablation/jobs/submit_ablate.sh --study groups
```

The default profile is `paper`, which queues the baseline and 13 ablations.
HAL paper runs default to `SUBSET=0.25` and `PHENONN_MEM=120G`. Override with
`SUBSET=...` or `PHENONN_MEM=...` for larger nodes. Extra arguments are
forwarded to `gen_jobs.py`.

Local smoke run:

```bash
PROFILE=smoke PHENONN_LOCAL=1 PHENONN_SITE=local \
  bash analysis/feature_ablation/jobs/submit_ablate.sh
```

Write the scripts without submitting them:

```bash
OUTPUT_DIR="$FA_ROOT" PHENONN_DRY_RUN=1 PHENONN_SITE=hal \
  bash analysis/feature_ablation/jobs/submit_ablate.sh --study features
```

## `submit_combo.sh`

Generates the fixed model and size sweep. Each configuration gets a baseline
and one ablation. Use `--skip-baseline` to reuse existing baselines.

```bash
OUTPUT_DIR="$FA_ROOT" PHENONN_SITE=hal \
    bash analysis/feature_ablation/jobs/submit_combo.sh
```

```bash
OUTPUT_DIR="$FA_ROOT" PHENONN_SITE=hal \
    bash analysis/feature_ablation/jobs/submit_combo.sh --skip-baseline
```

Submit combo only after the feature or group jobs have finished. On a
single-GPU quota, a later combo job can otherwise start before the remaining
feature jobs.

## `gen_jobs.py`

Writes the job scripts without submitting them. The scripts are site-agnostic:
they contain no partition, account, QoS, or memory directives. The wrappers
call `analysis/_cluster.sh` at submission time to add those options.

```bash
.venv/bin/python -m analysis.feature_ablation.gen_jobs \
    --profile paper --study all --output_dir "$FA_ROOT"
```

Choose one study:

```bash
.venv/bin/python -m analysis.feature_ablation.gen_jobs \
    --profile paper --study features --output_dir "$FA_ROOT"
.venv/bin/python -m analysis.feature_ablation.gen_jobs \
    --profile paper --study groups --output_dir "$FA_ROOT"
.venv/bin/python -m analysis.feature_ablation.gen_jobs \
    --profile paper --study combo --output_dir "$FA_ROOT"
```

Use `--subset 0.25` on HAL, or `--subset 0.5` on larger-memory systems.

The generated `submit_all.sh` checks the seven dataset inputs before `sbatch`
and submits the generated `run_*.sh` scripts.

## Options

Both wrappers accept:

- `PROFILE=paper|smoke`
- `OUTPUT_DIR=...`
- `SUBSET=...`: paper site subset; defaults to `0.25` on HAL and `0.5` otherwise
- `PHENONN_SITE=hal|leonardo|local`
- `PHENONN_LOCAL=1`
- `PHENONN_DRY_RUN=1`
- `PHENONN_DEPENDENCY=afterok:<jobid>`

Other options are passed to `gen_jobs.py`. `submit_combo.sh` also accepts
`--skip-baseline`.

Run one study at a time. To chain combo after another job, set
`PHENONN_DEPENDENCY=afterok:<jobid>`.

For the full workflow and result interpretation, see the
[feature-ablation guide](../README.md).
